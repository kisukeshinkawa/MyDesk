# 検証の結果と、ここから先の進め方

> **結論: この売買ロジックは株価指数に勝てませんでした。**
> 実際のお金を運用するなら、インデックスを買って放置するほうが合理的です。
> 銘柄スコア・チャート・ニュース・損切り/利確の目安は、
> 「自分で判断するための道具」としてはそのまま使えます。

2026-08-07〜08 に、成績が本物かどうかを一通り測りました。
DESIGN.md と README.md に書かれている設計は実装されていますが、
**「それで儲かる」という部分は検証の結果、支持されませんでした。**

---

## 1. 何を測ったか

| 検証 | 目的 | コマンド |
|---|---|---|
| 条件の一括比較 | 300銘柄・25年で360条件を比較 | `bash deploy/grid.sh run` |
| 安定領域の選定 | 年利1位ではなく、周辺条件も良い領域を選ぶ | `bash deploy/grid.sh best` |
| ウォークフォワード | 設定を決めた期間の**外**で通用するか | `bash deploy/wf.sh run off` |
| 約定コスト | スリッページを入れても優位が残るか | `bash deploy/slip.sh run` |
| 地合いフィルター | 判定方法を差し替えて比較 | `bash deploy/regime.sh run` |
| 連動性(相関) | 集中回避・β調整などが効くか | `bash deploy/corr.sh verify` |

指数との比較は必ず**同じ期間**で行います（25年通期の指数と6年の結果を比べない）。

## 2. 結果

### 2-1. 指数に勝てない

期間外(ウォークフォワード)で設定を選び直し、約定コストを4段階入れて測定:

| 見込む約定コスト | 年利 | 同じ期間の指数 | 差 |
|---|---|---|---|
| ズレなし(参考) | 7.31% | 10.25% | **-2.94** |
| 片道0.05% | 8.59% | 10.25% | **-1.66** |
| 片道0.10% | 7.07% | 10.25% | **-3.18** |
| 片道0.20% | 9.46% | 10.25% | **-0.79** |

**4段階すべてで負け。** コストをゼロにしても勝てません。

さらに重要なのは、**コストを増やしたのに成績が上下している**こと
(7.31→8.59→7.07→9.46)。コストが増えれば成績は必ず下がるはずです。
そうならないのは、**各コスト水準で選ばれる設定が毎回変わり、
その差のほうがコストの影響より大きい**ため。
つまり **優位性が、設定選びのブレより小さい**。これが決定的な証拠です。

同じ期間外テストで、候補を144通り→36通りに絞っただけで
年利は **11.25% → 7.31%** に落ちました。11.25% も「144通りから当たりを引いた」数字です。

### 2-2. 地合いフィルターは有害だった（唯一の確かな発見）

「指数が200日線の上のときだけ買う」という定番ルールを外すと、
**3期間すべてで成績が改善**しました。

| 地合い判定 | 年利 | 最大下落 | 効率 |
|---|---|---|---|
| 200日線の上だけ(旧・既定) | +6.18% | -29.1% | 0.212 |
| **外す** | **+10.94%** | **-27.1%** | **0.404** |

個別銘柄のスコアに既にトレンドが入っているため、
指数で二重に絞ると**売買機会を削るだけで守りにもなっていない**
(下落幅が改善しているのが証拠)。

ただし外しても指数には勝てません。

### 2-3. 連動性(相関)は効かない

集中回避・牽引役の順張り・β調整サイズを、性格の違う6設定で検証:
**どれも全設定で改善せず**(最良で2/6)。相関は画面での判断材料に留めます。

## 4. これから変更を加えるときの手順

**思いつきを検証せずに採用しないこと。** 上記の不具合の多くは、
それを怠ったことが原因です。

1. 変更を入れる
2. `bash deploy/wf.sh run off` — 期間外で通用するか
3. `bash deploy/slip.sh run` — 約定コストを入れても残るか
4. 同じ期間の指数を上回っているか確認
5. 上回らなければ**採用しない**

### 採用の基準（緩めないこと）

- **全期間で改善**していること。2/3 や 2/4 は採用しない
- 数字を見た**後**に「この条件でだけ効く」と説明を思いつくのは**後付け**。
  切り分けの検証を追加してから判断する
- 取引回数が大きく減る改善は、「入れ替え」でなく「見送り」の可能性を疑う
- 年利1位は「たまたま当たった条件」。周辺条件も同水準か確認する
  (`bash deploy/grid.sh best`)

画面上部の警告表示は S3 の検証結果から自動生成されます
(`action: "reality"`)。**本当に指数を上回れば、警告は自動的に消えます。**

## 5. 測っていないこと

- **生存バイアス**: 銘柄リストは現在も上場している企業のみ。
  倒産・上場廃止を含まないため、成績は通常1〜2ポイント良く出ます。
  ただし**それを差し引く前に既に指数へ負けている**ため、
  測っても結論は変わりません。
- **実運用の記録**: デモ口座の決済実績はまだほぼゼロです。
  検証値と実際のズレを見るには、最低10回以上の決済が必要です。

## 6. 運用コストについて

検証のため Lambda のメモリを 10240MB に上げています。
日次ジョブ5本＋毎時の自動売買が動くので、**月$25〜40程度**かかる想定です。
検証を頻繁に行わないなら、`deploy/01-deploy-lambda.sh` を
`MEMORY=2048 bash deploy/01-deploy-lambda.sh` で戻せます
(重い検証を回すときだけ10240に上げる)。

不要なジョブは個別に止められます:

```bash
aws events disable-rule --name mytrade-flow --region ap-northeast-1
```
